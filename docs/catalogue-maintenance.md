# 地点库维护与扩展

主站地点库位于 `data/shanghai.catalogue.json`。名称、地址、来源、体验字段和未来搜索所需的位置资料在同一条记录中维护。新增地点不再需要修改页面或逐个增加程序中的地点编号。

## 本轮边界

这是独立的数据文件，仍随网站版本发布。尚未连接在线数据库、后台录入界面或外部地点服务。修改数据后仍需校验并发布网站，用户才会看到更新。

未启用距离限制时，现有60条记录和48种条件组合的推荐结果保持一致。地址、来源及原查阅日期沿用；数据结构升级日期为2026-09-15，不代表重新核实了营业信息。

## 添加一个地点

1. 在地点库的 `places` 数组中新增完整记录。可复制相近类型的结构，但必须逐项核对并替换内容。
2. 使用从未使用过的正整数 `id`。编号会关联用户收藏；停用编号应写入 `retiredIds`，不能分配给其他地点。2、3、4为早期演示编号，永久保留不用。
3. 填写名称、具体地址、已定义片区、分类和来源链接。来源应指向具体资料页；不知道的费用、预约或营业时间明确写待确认。
4. 维护 `visit`：建议时长区间、活动类型、室内外、交流方式、参与方式、预约提醒等。此部分属于编辑建议。它们直接供推荐规则读取，无需另外添加编号映射。
5. 独立地点用自己的 `id` 字符串作为 `visit.cluster`。同一空间与其商户共用稳定的分组值，避免同时占据多个推荐位。只有真正属于同一空间时才合并，不能把整条街当成一个空间。
6. 没有核实坐标时保持 `geo.status=pending`，`point/source/checkedAt` 均为 `null`。不要填街区中心、猜测坐标或用0代替未知。
7. 尚未检查实际运营情况时保持 `operations.status=not_checked`，其他两项为 `null`。查阅历史介绍不等于确认当天开门。
8. 如已取得外部地点服务的稳定编号，写入 `externalRefs` 的 `provider/placeId`，以便后续去重。没有时保留空数组。
9. 更新 `dataUpdatedAt`；`checkedAt` 只填写实际查阅资料的日期。运行 `node scripts/validate-catalogue.mjs` 检查数据，随后构建、验证并发布。

检查会拦截重复编号、重复名称与地址、复用外部编号、无效片区、缺失来源、不完整坐标、非法日期和颠倒的停留时长。构建流程已接入该检查；数据不符合要求时会停止构建。

## 坐标与范围搜索的前置要求

`geo.status=verified` 必须同时提供：

| 字段 | 要求 |
| --- | --- |
| `point.latitude` / `point.longitude` | 有来源的数值坐标，保持纬度/经度顺序 |
| `point.crs` | 明确标注WGS84、GCJ-02或BD-09；后续距离计算不能混用坐标系 |
| `source` | 用于核对该地点位置的具体资料页 |
| `checkedAt` | 实际完成核对的日期 |

格式检查能发现数据结构问题，不能代替对真实地点位置的核对。2026-09-15已核对5处高德地点标记（GCJ-02）：衡山公园、Arabica武康路店、Franck Bistrot、上海话剧艺术中心和襄阳公园。其余55处保持待核对。坐标并非入口或楼层位置，不能当作步行导航。来源和高德稳定编号逐条保存在记录中。

高德坐标系依据：[高德官方坐标转换说明](https://lbs.amap.com/api/javascript-api/guide/transform/convertfrom)。不同坐标系不直接计算距离；没有进行隐式转换。

首页“附近找找”是可选试用入口：选择已核对的地点作为起点，筛选500米、1公里、2公里或3公里的直线范围。筛选依据未取整距离，展示距离约数。页面显示可计算数量与被排除数量，未知坐标不计作范围外；清除距离保留其他筛选条件。下一轮继续补齐武康—衡山片区位置资料。外部搜索负责发现候选，地点库负责保留来源和更新状态，推荐规则负责判断当次适合度。

## 持续更新

来源查阅、运营状态与坐标核对分别记录。没有更新来源时，不批量刷新日期。`operations` 中的营业、歇业或临时关闭状态需要记录当次来源和日期，尚未接入实时状态判断。

外部服务自动更新和不同城市的数据载入属于后续工作。附近搜索仅覆盖已核对地点，不能宣称覆盖全部周边场所、实时营业或自动发现新地点。
